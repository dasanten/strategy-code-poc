# What is generated

Some files in the repo are written by a program from the Rust crates, so the client reads the
server's own types, numbers and tables instead of a copy typed again (ADR 0030). They are never
edited by hand and never merged by hand: on a conflict, merge the sources, run `pnpm generate` and
commit what it writes.

## The outputs

| Output | Command | Written by | From |
| --- | --- | --- | --- |
| `packages/shared-types/src/generated/` (one `.ts` per type, `index.ts`, `constants.ts`) | `pnpm types:rust` | `crates/csp-server/src/bin/export-types.rs` | the `#[derive(TS)]` types across the crates, listed in `crates/csp-server/src/client_types.rs`; the constants that are not balance numbers in `crates/csp-server/src/client_constants.rs` |
| `packages/balance/balance.json`, `packages/balance/balance.d.ts`, `packages/balance/src/constants.ts` | `pnpm balance:rust` | `crates/csp-shared/src/bin/write-balance.rs` | the balance numbers in `crates/csp-shared/src/balance/`, exported by `crates/csp-shared/src/balance_export.rs` |
| `packages/balance/src/specs.ts` | `pnpm balance:rust` | the same | the building, good, vessel and siege machine specs, exported by `crates/csp-shared/src/spec_export.rs` |
| `packages/lang-wasm/script-data.json` | `pnpm script-data:rust` | `crates/csp-lang-wasm/src/bin/script-data.rs` | the script tables in `crates/csp-sim/src/script_tables/` (`docs/adding-content.md`) |
| `packages/lang-wasm/generated/` (not committed) | `pnpm wasm:build` | `scripts/wasm-build.mjs` | `crates/csp-lang-wasm`: the script checker and the rules (`docs/wasm-rules.md`) |
| `apps/web/src/assets/pixel/*.png`, `apps/web/src/map/pixel-slices.ts` | `pnpm art:pixel` | `scripts/pixel-art.mjs` | `art/pixel/*.aseprite` (needs Aseprite; `docs/art.md`) |

`pnpm generate` runs the first three commands (`types:rust`, `balance:rust`, `script-data:rust`):
everything committed that comes from the crates. The hand-written parts of those packages are
`packages/shared-types/src/index.ts`, `packages/balance/src/index.ts`,
`packages/balance/src/formulas.ts` and `packages/lang-wasm/src/` (the client's wrappers around the
module: `index.ts`, `rules.ts`, `areas.ts`, `script-data.ts`).

`pnpm wasm:build` needs no committing: `packages/lang-wasm/generated/` is in `.gitignore`.
`pnpm typecheck` and `pnpm test` build it first; a build with nothing to do takes about a second.
The `Dockerfile` builds it in a stage of its own, copies it in and sets `CSP_WASM_PREBUILT=1`.

`pnpm art:pixel` runs only when the art changes; nothing checks that its outputs are current.

## How a stale one is caught

- **`pnpm check <base>`** (`scripts/check-generated.mjs`, its first step): when the change touches
  `crates/`, `Cargo.*` or a generated file, it runs `pnpm generate` and fails if a file changed.
  The files it compares are those `.gitattributes` marks `linguist-generated`.
- **`pnpm check:rust`** (the crates' tests): each generator has a test that fails while its output
  differs from what it would write:
  - `the_generated_types_are_not_stale` in `crates/csp-server/src/client_types.rs`;
  - `crates/csp-shared/tests/balance_export.rs`, covering every file `balance:rust` writes,
    `specs.ts` too;
  - `crates/csp-lang-wasm/tests/script_data.rs`.
- **`.gitattributes`** marks the outputs `merge=union`, so a merge never stops on them; the merged
  text is thrown away by regenerating.

## Snapshots a test writes on request

Not generated by `pnpm generate`, and not merged by hand either: a test compares against them and
writes them again when asked.

| File | Written by | When |
| --- | --- | --- |
| `crates/csp-sim/tests/client_twins.json` | `CSP_WRITE_TWINS=1 cargo nextest run -p csp-sim client_twins` | a TypeScript twin of a Rust rule is added or changed (`docs/wasm-rules.md`) |
| `crates/csp-sim/src/npc_scores/neutral.json` | `CSP_WRITE_NEUTRAL=1` with the test in `crates/csp-sim/src/npc_scores/neutral_tests.rs` | the NPC planning pass changes on purpose (ADR 0039) |

## Frozen, never written

`crates/csp-sim/fixtures/` holds the frozen output of the TypeScript game from the cutover (T88.6,
`crates/csp-sim/fixtures/README.md`). Nothing writes it any more: a rule change that a fixture
comparison fails on replaces that comparison with a Rust test of the new rule.
